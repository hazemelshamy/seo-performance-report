Issue 01 — Critical Priority

🔴 Critical Mobile Redirect: animaat.com → Google Play Store

The Lighthouse mobile audit revealed that accessing https://www.animaat.com/ on mobile triggers a redirect to https://play.google.com/store/apps/details?id=com.animaat.app&pli=1. This is a catastrophic configuration issue: Google's mobile crawler (Googlebot-Smartphone) follows this redirect and indexes the Play Store page instead of animaat.com. This is confirmed by the mobile PageSpeed SEO flag: "Document does not have a valid rel=canonical — Points to another hreflang location (Play Store)" and the mobile SEO score dropping to 85/100.

  • Impact: Mobile Lighthouse score penalised (Performance 36/100 vs actual site's 40/100)
  • Impact: Google may be indexing the Play Store page as Animaat's mobile URL — catastrophic for mobile rankings
  • Impact: Users on mobile may be redirected away from the website, losing all mobile web traffic
  • Impact: The hreflang tag pointing to Play Store is invalid and confuses Google's language/region signals
✓ Solution

1. Remove or fix the mobile redirect immediately. Check the .htaccess file, server-side code (PHP/Node), or WordPress/plugin settings for any User-Agent-based redirect targeting mobile browsers. The redirect logic sending mobile visitors to the Play Store must be removed or converted to a smart banner (Google-supported app install prompt).

2. Implement a Smart App Banner instead: Add the following to the <head> of your pages:

<meta name="apple-itunes-app" content="app-id=YOUR_APP_ID">
<link rel="manifest" href="/manifest.json">

3. Fix or remove the hreflang tag pointing to the Play Store — hreflang must reference actual web pages, not app store URLs.

4. After fixing: Run Google Search Console's URL Inspection tool on the homepage, request re-indexing, and monitor the mobile coverage report for 2–4 weeks.

Issue 02 — Critical Priority

🔴 Mobile Performance Score 40/100 — Core Web Vitals Failing

PageSpeed Insights records mobile FCP at 12.5s, LCP at 23.5s, TBT at 610ms, and Speed Index at 12.5s — all catastrophically beyond acceptable thresholds. Since Google uses mobile-first indexing, these scores directly suppress Animaat's search rankings across all devices. The primary culprits identified by both tools are:

  • Unused JavaScript: 1,121 KiB (PageSpeed mobile) — loading JS that is never executed on the current page
  • Render-blocking requests: Est. 2,450ms wasted (Lighthouse desktop) — resources blocking first paint
  • Document request latency: Est. 1,970ms overhead before page data begins transferring
  • Font display issues: Est. 1,730ms delay from fonts not loading optimally
  • Network payload too large: Total mobile payload = 4,814 KiB (well above 1,600 KiB recommended)
  • No HTTP/2 or HTTP/3: Modern HTTP upgrade could save est. 1,720ms
✓ Solution — Prioritised Action List

1. Implement Code Splitting & Lazy Loading: Use dynamic import() in JavaScript to load only code needed for the current view. Add loading="lazy" to all below-fold images.

2. Fix Font Display: Add font-display: swap to all @font-face declarations to prevent render-blocking while custom fonts load.

3. Eliminate Render-Blocking Resources: Move non-critical CSS to async load. Add defer or async attributes to non-critical script tags.

4. Enable HTTP/2 on the server — contact your hosting provider. HTTP/2 allows multiplexing of requests, eliminating round-trip delays between resource requests.

5. Implement proper caching headers: Add Cache-Control: max-age=31536000, immutable for static assets (JS, CSS, images). Lighthouse flagged est. 4,048 KiB that could be cached but isn't.

6. Compress and serve modern image formats: Convert all images to WebP/AVIF. The image delivery improvement alone could save 866 KiB per page load.

7. Reduce unused CSS: 747 KiB of CSS is loaded but unused. Use PurgeCSS or manual audit to remove dead styles. For WordPress, dequeue unused plugin stylesheets.

Issue 03 — High Priority

🟠 Desktop Performance 59–75/100 — Significant Optimisation Headroom

While desktop performance is better than mobile, the Lighthouse score of 59/100 and PageSpeed score of 75/100 show substantial gaps. Desktop LCP is 2.5s (at the very edge of "Good") and FCP is 1.5s (acceptable but improvable). Additional flags include: render-blocking requests (est. 2,450ms savings), legacy JavaScript (est. 157 KiB unnecessary polyfills), unused CSS (747 KiB), and an oversized network payload (3,908 KiB via Lighthouse / 4,715 KiB via PSI).

✓ Solution

1. Audit and remove Legacy JavaScript: Use Babel preset-env with targeted browserslist config. Modern browsers (Chrome 90+, Safari 14+) do not need many polyfills. Removing legacy JS saves 157 KiB immediately.

2. Preload the LCP element: Identify the Largest Contentful Paint element (usually the hero image or main heading) and add <link rel="preload"> in the document head to begin loading it immediately.

3. Implement resource hints: Use rel="preconnect" for all critical third-party origins (CDNs, font providers, analytics) to reduce TCP handshake latency.

4. Add source maps for JavaScript: PageSpeed flags "Missing source maps for large first-party JavaScript" — add source maps to improve debugging and reduce console errors.

Issue 04 — High Priority

🟠 Low Overall CTR (1.72%) — 8,080 Impressions Converting Poorly to Clicks

Animaat generates significant impressions but only converts 1.72% to clicks overall. The US market — Animaat's largest by impressions (3,487) — achieves only 0.40% CTR at position 15.19. High-impression pages like /rescue-dog-nutrition-guide/ (1,370 impressions, 0.29% CTR) and /rescue-cat-indoor-transition-guide/ (500 impressions, 0.20% CTR) are failing to attract clicks despite substantial search visibility.

✓ Solution

1. Rewrite meta titles and descriptions for high-impression, low-CTR pages. Focus on emotional triggers, specificity, and search intent matching. Example: instead of "Rescue Dog Nutrition Guide | Animaat", use "How to Safely Refeed a Starving Dog: The Complete Recovery Protocol."

2. Add structured data (FAQ Schema, HowTo Schema, Article Schema) to content pages. Rich results take more SERP real estate and dramatically increase CTR. Animaat's FAQ pages are natural candidates.

3. Target "position 11–20" pages for ranking improvements. Pages at positions 11–20 are near page 1 with small improvements needed. The rescue cat page (position 9.91), rodent transport page (8.17), and sanctuary space page (7.23) are all close to page 1 territory.

4. A/B test meta descriptions using the GSC performance data as baseline. Track CTR changes after each revision.

Issue 05 — Critical Priority

🔴 Impression Collapse: January Peak (1,712) → April Drop (254) → May Near-Zero

After reaching a peak of 1,712 impressions in January 2026, impressions have declined sharply — dropping to 963 in March, 254 in April, and near-zero in May 2026 (only 42 impressions, likely incomplete data). This dramatic decline suggests either: (a) a Google algorithm update affected ranking positions, (b) content became less relevant or was thin/duplicate, (c) technical issues caused indexation drops, or (d) the redirect issue (Issue #01) is causing Google to stop crawling the site entirely on mobile.

✓ Solution

1. Conduct an immediate Google Search Console Coverage audit. Check for "Excluded" pages, crawl errors, or noindex tags added inadvertently.

2. Correlate the decline with Google algorithm update dates. Major updates in early 2026 (Core Update, Spam Update) may have affected rankings. Review Google Search Status Dashboard for update dates.

3. Fix the mobile redirect (Issue #01) immediately — this is the most likely cause of Google reducing crawl activity, as a site that redirects mobile Googlebot to the Play Store signals misconfiguration.

4. Conduct a content quality audit. Identify thin pages (under 500 words), duplicate content, or pages with high impressions but no meaningful content improvement since publication.

5. Increase publishing frequency of new content on established topics where Animaat already ranks (rescue dog care, rabbit care, bird enrichment) to signal freshness to Google.

Issue 06 — High Priority

🟠 Best Practices Score 54/100 (Mobile) — Security & Trust Deficits

Both Lighthouse and PageSpeed flag the following Best Practices failures: (a) Does not use HTTPS for all requests — 1–2 insecure HTTP requests found within the page; (b) Uses third-party cookies — 5 cookies flagged; (c) Browser errors logged to console; (d) Issues logged in Chrome DevTools Issues panel; (e) No strong HSTS policy.

✓ Solution

1. Fix mixed content (insecure HTTP requests): Open Chrome DevTools → Security tab and identify which resources load over HTTP. Update all asset URLs to use HTTPS. This is usually caused by hardcoded HTTP URLs in the database (common in WordPress after SSL migration).

2. Implement HSTS (HTTP Strict Transport Security): Add the following header at the server/nginx level:

Strict-Transport-Security: max-age=31536000; includeSubDomains; preload

3. Audit and minimise third-party cookies. Review all installed plugins, scripts, and third-party services. Remove or replace any using deprecated or tracking cookies that conflict with privacy standards.

4. Resolve all browser console errors — see Issue #08 for detailed JS error resolution.

Issue 07 — High Priority

🟠 Low Engagement Depth: 1.35 Pages/Session, 15s Active Time, 44.5% Scroll Depth

Clarity data reveals that despite acquiring 871 sessions, users explore very little of the site: 1.35 pages per session (nearly single-page visits for most users), only 15 seconds of active interaction time, and a 44.5% scroll depth indicating most users never reach the bottom half of any page. The 2.3% quick-backs (20 sessions) suggest search intent mismatch — users arrive and immediately leave.

✓ Solution

1. Add prominent internal linking. Every blog/article page should include 3–5 contextual links to related content. Use "Related Articles" or "You May Also Like" sections above the fold.

2. Improve above-the-fold content quality. The 44.5% scroll depth and 15s active time indicate users make decisions in the first screen. Ensure the value proposition, key content, and CTAs are visible without scrolling.

3. Add interactive elements that drive engagement: comment sections, pet profile creation prompts, quizzes (e.g. "What's your pet's care style?"), or community joining CTAs. These extend session duration measurably.

4. Implement exit-intent content suggestions. When a user is about to leave an article, show a relevant content recommendation to keep them on site.

5. Review quick-back sources in Clarity recordings to identify which pages are producing rapid exits and why (content mismatch, load failure, or poor mobile UX).

Issue 08 — High Priority

🟠 JavaScript Errors (9 Total) & Dead Clicks (4.13%)

Clarity detected 9 total JavaScript errors across sessions: 44.44% are "is not defined" errors, 11.11% each are "is not a function," "illegal invocation," and "return statements are only valid inside functions." Additionally, 4.13% of sessions (36 sessions) recorded dead clicks — users clicking on elements that do not respond. These errors directly degrade user experience and indicate code quality issues.

✓ Solution

1. Address "is not defined" errors (highest frequency): These typically indicate variables or functions being called before they are declared, or dependencies loaded out of order. Use browser DevTools (Console tab) to identify exact line numbers and script files. Ensure all dependencies load before the scripts that depend on them.

2. Fix dead clicks using Clarity Heatmaps. Open Clarity → Heatmaps → Dead Clicks to see exactly which page elements are receiving clicks but not responding. Common causes: CSS elements styled as buttons without click handlers, broken links (href="#"), or elements covered by invisible overlays.

3. Implement error monitoring. Integrate a tool like Sentry or LogRocket to capture all JavaScript errors in production with full stack traces. This transforms reactive debugging into proactive monitoring.

4. Run a systematic code audit for all inline event handlers and ensure no function references exist to undefined callbacks.

Issue 09 — Medium Priority

🔵 SEO Content Gaps: High-Impression Keywords Converting 0 Clicks

Several high-impression queries are generating zero clicks, representing significant unrealised traffic potential. Queries such as "best rabbit habitat settings for optimal comfort" (127 impressions, pos. 42), "domestic bird care" (110 impressions, pos. 50), and "how to feed an emaciated dog" (76 impressions, pos. 37) confirm Google recognises Animaat's topical relevance but the content is ranked too deep to attract clicks. Additionally, Lighthouse flags 4 links without descriptive text across both desktop and mobile, which is an SEO content quality signal.

✓ Solution

1. Create or optimise dedicated landing pages for the top zero-click queries. For "domestic bird care" (pos. 50 with 110 impressions), publish a comprehensive, structured guide with H2 headings matching sub-queries, FAQ sections, and rich media. Target position 10 and below.

2. Fix non-descriptive link text. Audit all <a> tags and replace generic text like "click here," "read more," or icon-only links with descriptive text that tells users and Google what the destination page contains.

3. Build topic clusters. Group related content (e.g. all rabbit care articles) under a single pillar page that links to all sub-articles. This strengthens topical authority and can lift entire clusters in rankings simultaneously.

4. Pursue featured snippet optimisation for question-based queries (who, what, how, why). Format answers with concise 40–60 word paragraphs directly answering the query, preceded by the query as an H2 or H3 heading.

Issue 10 — Critical Priority

🔴 Invalid rel=canonical & hreflang Conflict on Mobile

PageSpeed Insights mobile reports: "Document does not have a valid rel=canonical — Points to another hreflang location (https://play.google.com/store/apps/details?id=com.animaat.app)". This means the canonical tag on the mobile version of the homepage is pointing to the Play Store — telling Google that the canonical (authoritative) version of animaat.com is a Play Store listing. This is a critical SEO signal error that can cause Google to deindex or demote the actual website.

✓ Solution

1. Immediately audit the rel=canonical tag on all pages, especially the homepage. The canonical should always point to the page itself (self-referencing canonical) or to the desktop equivalent URL — never to an app store.

2. Remove or fix any hreflang tags pointing to app store URLs. Valid hreflang must reference web URLs only. If you need to indicate an app, use platform-specific meta tags (apple-itunes-app, google-play-app) rather than hreflang.

3. Use GSC's URL Inspection tool to verify what Google sees as the canonical URL for your homepage. If it returns the Play Store URL, submit for re-indexing immediately after fixing.

4. Check for conditional canonical implementation in WordPress plugins (Yoast, RankMath) or theme templates. Some plugins conditionally output different canonicals for mobile user agents.
